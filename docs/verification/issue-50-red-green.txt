Limitations:
- Migration is deliberate mapping, not automatic account matching or copying. Indexer-only
  accounts need an explicitly created owner. The selector is exact-name text, not a dropdown.
- Shared consumers retain stale legacy cookie/credential fields; downgrade ignores the selector.
  Owner legacy fields are current; consumers require deliberate reconciliation/copy before
  downgrade. Emptying a selector reactivates its retained legacy account settings.
- Owner names are administrative mappings: rename requires updating selectors; deleting/recreating
  the same unique name selects the replacement. Disabled owners are allowed; only enabled
  download clients are scheduled hourly. Indexer-only use validates at search/Test.
- Ordinary host/API settings edits are outside plugin compare-before-write coordination. Manual
  host cookie paste is retained; ReplaceIdentityAsync is the validated transactional import seam.
  No host database transaction fault injection or cross-process compare-and-swap is claimed.
- Fixtures prove regressions, not production/runtime/live-account qualification. No browser flow,
  Subsonic implementation, passive rotation or indefinite session-life guarantee is added.
