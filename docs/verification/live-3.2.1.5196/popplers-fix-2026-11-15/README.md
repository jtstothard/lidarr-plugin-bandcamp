## Root cause and fix

The earlier apex-only cookie boundary stripped the identity from Bandcamp's numbered `popplersN.bandcamp.com` download servers. The server then reported `ExpirationError` for a valid owned format link. This was **not proof that the purchase link or account identity had expired**. A controlled same-FLAC-URL comparison, changing only cookie presence (and anti-cache nonce), returned `err / ExpirationError` without identity and `ok` with a real download_url with identity. [Actual differential](identity-differential.json) contains only response classifications. A temporary visible Chromium check seeded only the existing owner identity, independently confirmed fan 67857, and observed successful browser status responses. [Browser output](visible-browser.txt) is not a fresh-login or helper-packaging qualification. No password login, CAPTCHA bypass, owner identity replacement or broad browser cookie export occurred.

The current public Bandcamp download bundle also exposed a protocol mismatch. Its statdownload request uses `.rand` and `.vrs=1`; `result` gates success, `url` describes the status request, and `download_url` (or, after explicit success, the original format link) identifies the file. `retry_url` belongs to an expired-free-download recovery branch; an empty retry_url alone does not establish download readiness. The parser now handles the actual `if ( window.Downloads ) { Downloads.statResult( {...} ) };` wrapper as data without executing JavaScript, recognizes the successful-result contract, and refuses failed status responses without requesting their metadata URL. A pointer-only compatibility path remains for older fixtures/servers. See [pinned actual bundle provenance](primary-source.json). This supersedes the earlier generic retry_url interpretation in the route-candidate preparation notes.

Account APIs and passive identity rotation remain restricted to the apex HTTPS origin. A separate internal download builder sends **only the canonical minimal identity cookie** to default-port HTTPS `popplers[0-9]+.bandcamp.com` URLs whose path begins `/download/` or `/statdownload/`, with no userinfo or fragment. It excludes arbitrary artist hosts, lookalike domains, unrelated paths, bcbits hosts and insecure endpoints. Archive redirects still drop identity permanently on an origin change, including a later return to the first host. No general cookie jar, redirect relaxation, TLS bypass, automatic login retry or statdownload polling was added. Unsafe initial archive URL components now fail with a fixed credential-free error before request construction.
